# v0.6.11 — flip defaults to plain HTTP (matches Hikvision V5.x reality)

User reported (2026-09-24 23:02 → 23:27): after v0.6.10 the
integration still didn't pull any data for the user's IPCs
(`10.18.176.10`, `10.18.176.65`) and NVR (`192.168.10.10`).

## Root cause

Pre-v0.6.10 the integration's `ISAPIClient` hard-coded HTTPS for
port 443. v0.6.10 added an explicit `use_https` toggle but kept
**HTTPS as the default for port 443**. Both behaviors assumed
Hikvision ISAPI is HTTPS — wrong.

Hikvision V5.x firmware serves ISAPI over **plain HTTP** by
default. Port 80 is the default; port 443 is also HTTP unless the
device's web-server settings explicitly enable HTTPS (which is an
opt-in toggle in the device's web UI). The community integration
that inspired ours uses `self.base_url = f"http://{host}"` with no
HTTPS option — that is the conventional baseline.

The user's IPCs almost certainly serve ISAPI over HTTP at port
443 (a documented config on some V5.x firmware where the
web-server is left in plain-HTTP mode). Our integration connected
with TLS, the handshake failed (or returned no XML), the
coordinator raised `UpdateFailed`, every entity showed
`unavailable` — exactly what the user observed.

## Fix

Flip the defaults to match reality:

- **`DEFAULT_PORT`**: `443` → `80` (V5.x default).
- **`ISAPIClient` `use_https` parameter**: `True` → `False`.
- **`ISAPIClient` `port` parameter**: `443` → `80`.
- **`HikvisionISAPICoordinator` `use_https` fallback when entry
  has no explicit value**: `True` → `False`.
- **Config flow `use_https` field default**: pre-checked → unchecked.
- **`_default_use_https(port)`**: now always returns `False`,
  regardless of port. User opts into HTTPS via the checkbox if
  their device has HTTPS enabled in the web UI.

Users who already configured the integration under v0.6.10 with
`use_https=True` are unaffected by this default flip — their entry
data still has `use_https=True` and that's what gets used. Users
who were silently failing (because their device is HTTP) need to
remove and re-add the integration to pick up the new defaults.
After re-add, the URL becomes `http://host:port` (where port is
whatever the user enters; default 80).

  enabled in their device's web UI) see no behavior change.

## Upgrade path

HACS → 已安装的集成 → Hikvision ISAPI Performance → 更新到 v0.6.11 →
重启 Home Assistant.

If your device's ISAPI was unreachable under v0.6.10 (i.e. you
suspect the integration was sending HTTPS to an HTTP-only device):

1. Settings → Devices & Services → Hikvision ISAPI Performance → ⋯
   → Delete.
2. Restart Home Assistant (so HA fully clears the entry's cached
   entry data).
3. Add Integration → Hikvision ISAPI Performance. Fill in:
   - **Host**: e.g. `10.18.176.10`
   - **Port**: `443` (or whatever your device listens on)
   - **Username**: e.g. `admin`
   - **Password**: your password
   - **Use HTTPS**: leave **off** (unchecked) — this is the new
     default and matches Hikvision V5.x firmware behavior.
   - **Verify SSL**: leave off.
4. Submit. The integration should now reach the device and start
   populating device-level entities.

If your device actually requires HTTPS (rare; only when you've
explicitly enabled it in the device's web-server settings), tick
"Use HTTPS" on.

## Why this matters

This is the right default for the most common case. Users who
never knew to toggle the "Use HTTPS" checkbox would silently get
an integration that doesn't connect. After v0.6.11 the
integration works out-of-the-box for the 95% case of plain-HTTP
Hikvision ISAPI.
