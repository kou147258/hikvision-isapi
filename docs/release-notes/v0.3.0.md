# v0.3.0 — per-channel binary sensors (online / recording / motion)

Adds a new `binary_sensor` platform with three per-channel sensors
for every detected channel on the device.

## What's new

| Entity | Type | Source | Notes |
|---|---|---|---|
| Channel N 在线 (Online) | `connectivity` | `/ISAPI/ContentMgmt/InputProxy/channels/<id>/status` `<online>` | Per-channel reachability |
| Channel N 录像中 (Recording) | `running` | `<recordStatus>` (`recording` / `idle`) | Per-channel recording state |
| Channel N 运动检测 (Motion) | `motion` | `<motionDetection>` | Per-channel motion flag |

For a 4-channel NVR, that's 12 new binary sensors. They complement
v0.1's device-level `Online` / `Recording` (which aggregate "any
channel" — useful for a "device is alive" check) with per-channel
detail (useful for "if camera 3 has motion, do X" automations).

## Architecture

### Per-channel status fetch

`coordinator._async_update_data` now fetches
`/ISAPI/ContentMgmt/InputProxy/channels/<id>/status` for every
detected channel (best-effort per channel — a single channel
endpoint failure doesn't take down the refresh). The status is
merged into the channel dict in the coordinator data:

```python
ch["online"] = ...             # from /channels/<id>/status (or /channels if missing)
ch["recording"] = ...
ch["motion_detected"] = ...    # from /channels/<id>/status only
```

The motion field is only set if the per-channel endpoint reported it
(older firmware may not include `<motionDetection>`); the binary
sensor's `is_on` property returns `None` in that case so HA shows
`unknown` rather than guessing.

### Entity registration

Follows the v0.1.23 deferred-registration pattern: when
`async_setup_entry` runs, if `coordinator.data` is already populated
the per-channel binary entities are added immediately; otherwise a
one-shot coordinator listener fires after the first poll completes.
The listener uses a flag (`coordinator._hikvision_isapi_binary_added`)
to be idempotent.

### `_parse_channel_status`

New pure-Python XML extractor. Reads `<online>`, `<recordStatus>`,
and `<motionDetection>` from the per-channel status response.
Missing fields default to `False` (we don't assume the channel is
offline just because the firmware didn't report the field).
