# v0.2.0 — storage, network interfaces, per-channel bitrate

Nine new sensors on top of v0.1's eight. The new endpoints
(`/ISAPI/ContentMgmt/storage`, `/ISAPI/System/Network/interfaces`,
`/ISAPI/Streaming/channels/1`) are best-effort: a small IPC that
doesn't implement them doesn't take down the coordinator refresh —
the per-sensor extractors return `None` and the entity shows
`unknown`.

## What's new

| Sensor | Type | Source | Notes |
|---|---|---|---|
| 存储总量 (Storage Total) | data_size (GB) | `/ISAPI/ContentMgmt/storage` totalCapacity | NVR / DVR |
| 存储使用量 (Storage Used) | data_size (GB) | `/ISAPI/ContentMgmt/storage` usedCapacity | NVR / DVR |
| 存储剩余 (Storage Free) | data_size (GB) | `/ISAPI/ContentMgmt/storage` freeCapacity | NVR / DVR |
| 存储使用率 (Storage Usage) | % (derived) | used / total × 100 | NVR / DVR |
| IP 地址 (IP Address) | text | `/ISAPI/System/Network/interfaces` IPAddress | first NIC |
| 子网掩码 (Subnet Mask) | text | `/ISAPI/System/Network/interfaces` subnetMask | first NIC |
| 默认网关 (Default Gateway) | text | `/ISAPI/System/Network/interfaces` DefaultGateway | first NIC |
| MAC 地址 (MAC Address) | text | `/ISAPI/System/Network/interfaces` MACAddress | first NIC |
| 通道 1 平均码率 (Channel 1 Bitrate) | data_rate (kbps) | `/ISAPI/Streaming/channels/1` videoAverageBitrate | main channel |

Total sensor count: **17** (8 from v0.1 + 9 from v0.2).

## Architecture

### Best-effort endpoint fetching

`coordinator._async_update_data` now fetches four endpoints in one
refresh cycle:

1. `/ISAPI/System/deviceInfo` (always)
2. `/ISAPI/System/status` (always)
3. `/ISAPI/ContentMgmt/InputProxy/channels` (always)
4. `/ISAPI/ContentMgmt/storage` (best-effort)
5. `/ISAPI/System/Network/interfaces` (best-effort)
6. `/ISAPI/Streaming/channels/1` (best-effort)

The last three are wrapped in their own try/except. A 404 (or any
`ISAPIError`) on one of them is logged at debug and the parser is
called with `None` — the resulting data dict has empty fields, and
the sensors report `unknown` / `None`. The coordinator's overall
refresh still succeeds.

### Parsers

Three new pure-Python XML extractors:

- `_parse_storage(root)` — reads `totalCapacity` / `usedCapacity` /
  `freeCapacity` (all in MB) plus the `status` field
  (`normal` / `exception`).
- `_parse_network_interfaces(root)` — reads each `NetworkInterface`
  block into a dict with `id` / `name` / `ip_address` /
  `subnet_mask` / `default_gateway` / `mtu` / `mac_address`. The
  `sensor.py` extractors read the first interface (most devices have
  one LAN port; multi-NIC devices will get the primary interface
  reported first by Hikvision).
- `_parse_streaming_channels(root)` — reads each `StreamingChannel`
  block's `videoAverageBitrate` (preferred) or `maxBitrate`
  (fallback), returns a `{channel_id: kbps}` dict. `sensor.py` reads
  channel 1 only — adding per-channel entities when more channels are
  discovered is deferred to v0.2.x.

### Sensor extraction

Three small helpers:

- `_mb_to_gb(mb)` — Hikvision reports storage in MB; HA prefers
  `DATA_SIZE` class which expects GB.
- `_storage_usage_pct(storage)` — `used_mb / total_mb × 100`,
  returns `None` if either side is missing.
- `_first_iface(data, field)` — return the requested field from
  the first network interface Hikvision reports.

## Tests
