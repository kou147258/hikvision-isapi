# v0.6.13 — XML namespace stripping (Hikvision's `xmlns=` decoration broke every parser)

User reported (2026-09-25 00:36): v0.6.12 lifted the "all unavailable"
state, but every sensor shows "未知" (unknown) — coordinator refresh
succeeds but every value parses to ``None``. No crash in logs.

## Root cause

Hikvision V5.x firmware serves ISAPI XML responses with a default
namespace declaration on the root element::

    <?xml version="1.0" encoding="UTF-8"?>
    <DeviceInfo xmlns="http://www.hikvision.com/ver20/XMLSchema" version="2.0">
      <model>DS-2CD2143G2-I</model>
      <serialNumber>SN-9876</serialNumber>
      ...
    </DeviceInfo>

Python's ``xml.etree.ElementTree`` follows the XML spec: when a
default namespace is set, every tag is parsed with the namespace
URI as a prefix. So ``<model>`` becomes
``{http://www.hikvision.com/ver20/XMLSchema}model`` internally.

The coordinator's XML parsers (e.g. ``_parse_device_info``) all
use **plain-tag** lookups: ``element.find("model")``. With
namespaced elements, this returns ``None`` for every field — the
parser silently falls back to ``""`` (for strings) or ``0`` (for
numeric sensor values).

Result:
- Device is reachable
- Coordinator refreshes fine
- But every sensor reads empty / 0
- HA shows "未知" (unknown) rather than the actual value

The pre-v0.6.13 unittests didn't catch this because every test
fixture used bare tags (``<model>``) without ``xmlns=...``.

## Fix

``isapi_client.py`` v0.6.13: both ``get_xml`` and ``put_xml`` now
strip ``xmlns="..."`` and ``xmlns:foo="..."`` declarations from
the response body *before* parsing. Plain-tag ``element.find(...)``
queries then match exactly.

```python
_XMLNS_RE = re.compile(
    r"""\s+xmlns(:[a-zA-Z][a-zA-Z0-9_-]*)?\s*=\s*"[^"]*"|"""
    r"""\s+xmlns(:[a-zA-Z][a-zA-Z0-9_-]*)?\s*=\s*'[^']*'"""
)

def _strip_xmlns(text: str) -> str:
    return _XMLNS_RE.sub("", text)

async def get_xml(self, path):
    text = await self.get_text(path)
    text = _strip_xmlns(text)
    return ET.fromstring(text)
```

The strip is regex-over-bytes — not a full XML-rewrite library.
We deliberately don't rewrite other attributes (``version="2.0"``
etc.) and don't touch the rest of the XML body. Hikvision is
picky about round-tripping its XML (see prior notes about
``ET.tostring`` mangling ``xmlns`` on child elements), so the
less we touch, the safer we are.

## Why we don't use namespaced queries instead

The alternative would be to update every ``element.find("model")``
in ``coordinator.py`` to ``element.find(".//{http://www...}model")``
or to register a default namespace. Both approaches require
changes spread across 10+ parser functions and are fragile
(future sensor additions must remember to namespace-qualify).

Stripping the namespace once at the transport boundary lets the
parser layer stay simple and namespace-naive — and matches what
the existing tests already exercise (bare XML).

## Tests

89/89 tests pass (was 79 before, +10 new in ``test_v0613_xmlns.py``):

- ``test_strip_xmlns_removes_default_namespace`` — pins the strip
  regex on the canonical Hikvision form.
- ``test_strip_xmlns_removes_prefixed_namespace`` — handles
  ``xmlns:ns1=...`` form too.
- ``test_strip_xmlns_handles_no_namespace`` — bare XML is
  unchanged.
- ``test_strip_xmlns_handles_multiple_xmlns`` — multiple
  declarations on one element.
- ``test_strip_xmlns_handles_single_quoted_xmlns`` — Hikvision
  occasionally uses single quotes.
- ``test_strip_xmlns_preserves_other_attributes`` — ``version``
  and other attrs survive the strip.
- ``test_get_xml_parses_namespaced_response`` — end-to-end
  ``get_xml`` against a Hikvision-shaped response, then runs
  ``_parse_device_info`` and asserts model/serialNumber/etc.
  populate correctly.
- ``test_get_xml_nested_schema_parses_with_xmlns`` — same
  end-to-end check for ``/ISAPI/System/status`` nested
  CPUList/MemoryList.
- ``test_get_xml_bare_xml_still_parses`` — regression for the
  no-namespace case (pre-existing XML tests must keep passing).
- ``test_v0613_manifest_version_bumped`` — pins manifest to
  0.6.13.
