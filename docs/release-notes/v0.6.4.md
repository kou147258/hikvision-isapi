# v0.6.4 — remove third-party repo references from docs

The `README.md` and several release notes referenced a third-party
Home Assistant Hikvision integration. Per maintainer request, all
such references are removed from this repo's user-facing docs:

- **`README.md`**: dropped the "disambiguate from …" blockquote and
  the "community `hikvision_isapi` integration … focuses on image /
  PTZ control" paragraph that followed it. The intro now states the
  rename to `hikvision_isapi_performance` (folder / domain / display
  name) without naming the other project. The "Distinct from
  hikvision-snmp" paragraph is unchanged.
- **`docs/release-notes/v0.6.0.md`**: the "To disambiguate from …"
  paragraph is rewritten as a generic "give this integration a
  distinct identity and avoid name collisions in HACS". The internal
  flag-rename table (which still references the old domain
  `hikvision_isapi` as a *historical* prefix) is unchanged because
  the names of those private attributes genuinely were that prefix
  before v0.6.0.
- **`docs/release-notes/v0.6.2.md`**: removed the cross-reference
  paragraph and the "Compatible with …" bullet.

## What did NOT change

- The integration's own `domain` (`hikvision_isapi_performance`)
  is unchanged. The rename is what gives us the unique identity
  in the first place.
- No code changes; no tests changes. 52/52 tests pass.
- HACS install URL, manifest.json, and config_flow are unchanged.

## Why not rewrite history completely?

The v0.6.0 / v0.6.1 release notes still mention the old domain
`hikvision_isapi` (the integration's *previous* domain, not the
other project's domain). Those references describe what was
renamed in *this* integration, which is factual history.
Releases v0.6.0 and v0.6.1 are already published to GitHub; the
JSON metadata on those releases is immutable per GitHub's release
API. Editing only the in-repo notes files is the right scope.
