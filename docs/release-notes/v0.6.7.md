# v0.6.7 — Basic-auth fallback + optional channels endpoint

User-reported regression (2026-09-24 21:44 → 22:19): after upgrading
to v0.6.5, every sensor under "Hikvision ISAPI Performance" was
marked `unavailable` (red `!` in the entity list). The earlier
v0.6.5 fix correctly caught `ISAPIAuthError` and converted it to
`UpdateFailed` so the coordinator stopped crashing with `NameError`,
but the underlying issue was still present: certain IPCs in the
user's fleet (10.18.176.10, 10.18.176.65) return **HTTP 403 with an
empty `WWW-Authenticate` header** on `/ISAPI/ContentMgmt/InputProxy/channels`,
and that single failing endpoint aborted the entire coordinator
refresh. The pre-v0.6.5 `NameError` had masked this by killing the
whole refresh with a NameError before it could even start; v0.6.5
exposed the real failure path.

## Two-part fix

### 1. Basic-auth fallback in `_read_response_text`

`isapi_client.py` previously only knew about Digest auth. When the
server returned 401/403 with an unrecognized `WWW-Authenticate`
header (empty, `Basic realm=...`, anything non-Digest), it raised
`ISAPIAuthError` immediately. Some Hikvision firmware accepts Basic
auth when their Digest path is misconfigured server-side — a known
quirk on older V4.x NVRs and early IPCs.

The retry now goes:

1. Original request (no auth).
2. On 401/403, parse `WWW-Authenticate`.
   - **Digest** challenge → build Digest header, retry.
   - **Anything else / empty / missing** → build Basic header,
     retry with Basic auth. If the Basic retry returns a Digest
     challenge (some devices advertise Digest on the second hit),
     follow that. If still 401/403 → raise `ISAPIAuthError`.

This matches what [the community `hikvision_isapi` integration](
recently added — the v1.3.0 "Basic auth fallback for old cameras"
release notes) does for the same reason.

### 2. Optional channels endpoint in coordinator

`coordinator.py::_async_update_data` previously treated
`/ISAPI/ContentMgmt/InputProxy/channels` as a required fetch.
Combined with the fix above, even a successful Basic retry can
still hit edge cases — and one failing endpoint should not
blackhole the entire refresh. The endpoint is now wrapped in
try/except: a 4xx/5xx here becomes an empty channels list, not a
full refresh failure. `deviceInfo` and `systemStatus` data
still reaches the sensor platform, so most sensors stay populated.

Trade-off: cameras that can't list channels don't get per-channel
entities (camera / recording switch / per-channel binary sensors
for online / recording / motion). They still get device-level
entities (model / firmware / cpu / memory / uptime / reboot /
storage / network / ptz-capable button).

## Tests

5 new tests in `tests/test_v067_basic_auth.py`:

- `test_build_basic_header_encodes_credentials` — RFC-correct
  base64 of `username:password`.
- `test_get_text_basic_auth_fallback_on_empty_www_authenticate` —
  the exact scenario from the user's logs (HTTP 403 + empty
  WWW-Authenticate → Basic retry succeeds).
- `test_get_text_basic_auth_fallback_on_basic_challenge` —
  explicit `WWW-Authenticate: Basic realm=...` triggers Basic.
- `test_get_text_digest_still_works_after_basic_fallback_added` —
  Digest path is unchanged for the common case.
- `test_get_text_basic_and_digest_both_fail_raises_auth_error` —
  when even Basic retry fails, we still surface `ISAPIAuthError`.

The pre-existing v0.6.3 test `test_get_text_unrecognized_www_authenticate_raises_auth_error`
was updated to assert the new behavior: 2 requests (original +
Basic retry), Basic header on retry. 64/64 tests pass.

## Compatibility

- No public-API changes. Same domain, same manifest version (we
  bumped to 0.6.6 in v0.6.6; this is the 0.6.7 release but we
  keep `manifest.json.version` at 0.6.6 since HA displays the
  last-bumped manifest value). Wait — see the next bullet.

- **`manifest.json.version` is now `0.6.7`.** Following the
  v0.6.6 lesson: every release bumps the manifest so HA shows
  the right version number.

## Upgrade path

HACS → 已安装的集成 → Hikvision ISAPI Performance → 更新到 v0.6.7 →
重启 Home Assistant. Devices that previously showed all sensors
as unavailable (because channels 403'd and killed the refresh)
should now show device-level sensors populated; cameras and
per-channel entities stay populated for devices whose channels
endpoint works. The 24 entities listed in HA's entity list
should split into:

- **Always populated** (work on every device):
  Model, Serial, Firmware, Device Status, CPU Usage, Memory Usage,
  Uptime, Uptime Hours, Reboot Count, CPU Model,
  SD Card Writes (IPC), Dome High-Temp Runtime (PTZ),
  Network IP / Subnet / Gateway / MAC, Channel 1 Average Bitrate,
  Reboot Device button.

- **Storage-only populated** (NVR / DVR): Storage Total / Used /
  Free / Usage %.

- **Per-channel populated** (devices where /InputProxy/channels
  works): Channel N Camera, Channel N Recording switch,
  Channel N Online / Recording / Motion binary sensors.
