# v0.1.0 — initial release

First public release of the Hikvision ISAPI integration. Distinct
from the [hikvision_snmp](https://github.com/kou147258/hikvision-snmp)
integration which talks to the same devices over SNMP — this one
uses ISAPI (Hikvision's HTTP API), which exposes control surfaces
(reboot, recording on/off, PTZ) and live snapshots that SNMP doesn't.

## What it does

Adds Hikvision NVR / IPC support to Home Assistant with:

- **Camera** — one entity per detected channel, still JPEG snapshot
  via `/ISAPI/Streaming/channels/{id}/picture`. The HA frontend
  refreshes the image on its standard camera component schedule.
- **Sensors** — model, serial, firmware, device status, CPU usage,
  memory usage, uptime, channel count. Eight sensors total.
- **Switch** — per-channel recording on/off
  (`/ISAPI/ContentMgmt/InputProxy/channels/{id}/capabilities?recording=On|Off`).
- **Button** — reboot the device (`PUT /ISAPI/System/reboot`).
- **Service** — `hikvision_isapi.ptz_goto_preset` to move a PTZ camera
  to a preset.

## Architecture

The integration follows the same patterns the user already knows
from hikvision_snmp:

- `ISAPIClient` is a small `aiohttp` wrapper with manual RFC 2617
  digest auth (aiohttp 3.8+ no longer ships `DigestAuth`).
- `HikvisionISAPICoordinator` is a `DataUpdateCoordinator` that polls
  `/ISAPI/System/deviceInfo`, `/ISAPI/System/status`, and
  `/ISAPI/ContentMgmt/InputProxy/channels` on a configurable interval.
- Entity platforms (`camera.py`, `sensor.py`, `switch.py`, `button.py`)
  follow the v0.1.23 pattern from hikvision_snmp: register
  system entities immediately, defer per-channel / per-camera
  entities to a coordinator listener (so they appear as soon as the
  first poll completes — no reload needed).
- `config_flow.py` provides the standard user form (host, port,
  username, password, verify_ssl) with a probe via
  `/ISAPI/System/deviceInfo`. `options_flow.py` exposes
  scan_interval.
- `services.py` registers the `ptz_goto_preset` service only when the
  device reports PTZ capability (so non-PTZ devices don't see a
  useless service in the dev-call dialog).

## Configuration

1. Settings → Devices & Services → Add Integration → Hikvision ISAPI
2. Enter host / port / username / password / verify_ssl
3. The integration GETs `/ISAPI/System/deviceInfo` to validate auth

## Tests

14 tests in `tests/test_isapi_client.py`:

- 3 tests for the digest challenge parser (`_parse_digest_challenge`)
- 2 tests for the digest response computation (`_compute_digest_response`)
  — including a hand-rolled reference value that matches RFC 2617
- 3 tests for the digest header builder (`_build_digest_header`)
- 6 tests for the coordinator's XML extractors (`_parse_device_info`,
  `_parse_system_status`, `_parse_channels`)

The HTTP transport layer itself is exercised by aiohttp's own test
suite — we don't mock aiohttp calls in the integration's tests
(brittle, and aiohttp already covers this).

## Limitations / deferred to v0.2

- **No live video streaming** — only still snapshots. The HA
  built-in camera component only supports still images. Continuous
  MJPEG via `/ISAPI/Streaming/channels/{id}/httppreview` is out of
  scope for v0.1; would require a custom camera frontend component.
- **ISAPI event stream** — `/ISAPI/Event/notification/alertStream` is
  declared in `const.py` but not consumed. v0.2 can add motion-detected
  binary sensors that don't need polling.
- **More endpoints** — network interfaces, disk info, user mgmt,
  etc. are exposed by ISAPI but not surfaced in v0.1. Add per demand.

## Compatibility

- aiohttp 3.9.0–3.13.x (3.14 dropped `DigestAuth`; this release
  doesn't need it because we implement digest manually)
- Home Assistant 2025.4+
- Python 3.11+
