# v0.6.9 — device-type-aware channel-list endpoint selection

User reported (2026-09-24 22:34+): after v0.6.8 the IPCs
(`10.18.176.10`, `10.18.176.65`) and the NVR (`192.168.10.10`) all
still got nothing — every per-channel entity was missing. The user
emphasized the integration needs to **distinguish IPCs from DVRs
(NVRs)**.

## Root cause

The coordinator hard-coded the NVR-side channel-list endpoint for
every device:

```python
channels_xml = await client.get_xml(ISAPI_INPUT_PROXY_CHANNELS)
```

`/ISAPI/ContentMgmt/InputProxy/channels` is **NVR-specific** — it
returns the list of mounted IPC channels on the NVR. On a standalone
IPC, this endpoint either returns HTTP 403 (the user's fleet) or
returns an empty / unexpected XML shape. Result: every IPC's
channel list was empty, so per-channel entities (camera,
recording switch, online / recording / motion binary sensors) were
never created.

Device-level entities (model, firmware, CPU, memory, uptime, etc.)
were unaffected because `/ISAPI/System/deviceInfo` and
`/ISAPI/System/status` are device-type-agnostic.

## Fix

After fetching deviceInfo, parse `deviceInfo.deviceType` to determine
the device type, then choose the right channel-list endpoint:

| device_type     | channel list endpoint                                | per-channel status endpoint                                |
|-----------------|------------------------------------------------------|------------------------------------------------------------|
| `ipcamera` (IPC) | `/ISAPI/Streaming/channels`                         | `/ISAPI/Streaming/channels/{id}/status`                     |
| `networkvideorecorder` (NVR), `dvr` | `/ISAPI/ContentMgmt/InputProxy/channels` | `/ISAPI/ContentMgmt/InputProxy/channels/{id}/status` |

**Fallback chain**: if the primary endpoint returns an error, the
coordinator tries the alternate (some firmwares only implement one
of the two). If both fail, we continue with empty channels list —
device-level entities still populate.

**Response-shape detection**: when parsing the channels XML, the
coordinator now checks the root tag:
- `<StreamingChannelList>` → use the new
  `_parse_streaming_channels_list` parser (IPC format, may have
  `<id>` or `<videoInputChannelID>`, optional `<online>` /
  `<recordStatus>`).
- `<InputProxyChannelList>` → use the existing `_parse_channels`
  parser (NVR format).

## Side effects of the fix

- IPCs at `10.18.176.10` / `10.18.176.65` should now get their
  per-channel entities populated (channel N camera, recording
  switch, online / recording / motion binary sensors). The
  `/Streaming/channels/{id}/picture` endpoint was already wired up
  in camera.py from v0.6.2.
- NVRs at `192.168.10.10` continue to work as before
  (`/ContentMgmt/InputProxy/channels` + `/StreamingProxy/channels/
  {id}/picture`).
- The `/Streaming/channels/{id}/status` endpoint may not exist on
  all IPC firmware — when it 404s, the coordinator falls back to
  the alt endpoint, then to "no per-channel status" (channel-level
  online / recording fall back to whatever the channels list
  reported).

## Tests

7 new tests in `tests/test_v069_device_type.py`:

- `test_parse_streaming_channels_list_extracts_id_and_name` — happy
  path on the new parser.
- `test_parse_streaming_channels_list_handles_missing_name` —
  fallback to "Channel {id}" placeholder.
- `test_parse_streaming_channels_list_falls_back_to_videoInputChannelID` —
  some IPCs omit `<id>` and provide `<videoInputChannelID>`;
  parser accepts both.
- `test_parse_streaming_channels_list_skips_entries_without_any_id` —
  defensive: drop entries with no id.
- `test_parse_streaming_channels_list_handles_empty_root` — None
  / empty XML both → [].
- `test_parse_streaming_channels_list_reads_optional_online_recording` —
  optional fields map correctly when present.
- `test_endpoint_constants_distinguish_ipc_vs_nvr` — the four
  endpoint constants are correctly defined in const.py.

76/76 tests pass.

## Compatibility

- No public-API changes.
- `manifest.json.version` bumped 0.6.8 → 0.6.9.
- Users whose devices worked under v0.6.8 see no behavior change
  (NVR path unchanged). Users with IPCs that previously had empty
  channel lists now get full per-channel entity coverage.
