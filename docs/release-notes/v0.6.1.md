# v0.6.1 — rename user-facing metadata to Hikvision ISAPI Performance

Hotfix on top of v0.6.0. The v0.6.0 rename commit (`custom_components/`,
manifest `domain`, module imports, `git mv`, force-push to the new
repo) was correct **internally**, but the user-visible name in HACS
still showed **Hikvision ISAPI** instead of **Hikvision ISAPI
Performance** — the old display name persisted because the
`hacs.json` `name` field and several README / manifest URLs / service
selector keys were not updated alongside the domain rename.

## What changed

- **`hacs.json` name field**: `Hikvision ISAPI` → `Hikvision ISAPI
  Performance`. This is the field HACS renders in the integrations
  store. Without this change the new repo continued to show as
  "Hikvision ISAPI" in HACS even though the manifest domain and
  folder were renamed.
- **`manifest.json`**: `documentation` and `issue_tracker` URLs now
  point at `kou147258/hikvision-isapi-performance` (previously still
  pointed at the deleted `kou147258/hikvision-isapi` repo).
- **`services.yaml` device selector integration key**: changed from
  `hikvision_isapi` to `hikvision_isapi_performance` so the PTZ
  service device selector picks devices from the correct domain.
- **`README.md`** (English + 简体中文): installation URLs, folder
  names, HACS / Settings search strings, and the
  `hikvision_isapi.ptz_goto_preset` service example all updated to
  the new naming.

## Compatibility

- Integration `domain` is unchanged from v0.6.0 (`hikvision_isapi_performance`).
- The service call signature also unchanged — only the prefix changes
  from `hikvision_isapi.ptz_goto_preset` to
  `hikvision_isapi_performance.ptz_goto_preset`. Existing HA
  automations referencing the old prefix will need to be updated.
- 35/35 tests pass.

## Upgrade notes

This release is published as a new version (v0.6.1) rather than a
silent force-push to v0.6.0 because:

- v0.6.0 was already pulled by HACS as the first public version under
  the new repo.
- Re-tagging v0.6.0 would either silently move the existing tag (and
  surprise anyone who already pinned v0.6.0) or fail because GitHub
  rejects reusing a tag SHA.
- Users already on v0.6.0 who don't need the metadata fix can stay
  there; the integration itself is identical at the code level.
