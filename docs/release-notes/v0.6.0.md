# v0.6.0 — integration renamed to `hikvision_isapi_performance`

To disambiguate from the existing community integration at
<https://github.com/JoshADC/hikvision_isapi> (domain `hikvision_isapi`),
v0.6.0 renames:

- **Folder**: `custom_components/hikvision_isapi/` →
  `custom_components/hikvision_isapi_performance/`
- **Manifest domain**: `hikvision_isapi` → `hikvision_isapi_performance`
- **Manifest name** (display in HA): `Hikvision ISAPI` →
  `Hikvision ISAPI Performance`
- **Module name** (Python import): `custom_components.hikvision_isapi`
  → `custom_components.hikvision_isapi_performance`

Both integrations can now be installed in HACS side-by-side without
the "this integration is already configured" error. The Python
folder uses underscores (not hyphens) because Python's import
machinery doesn't accept hyphens in package names.

## Internal flag renames

The deferred-entity-addition flags on the coordinator object were
renamed to match the new domain:

| Old | New |
|---|---|
| `_hikvision_isapi_binary_added` | `_hikvision_isapi_performance_binary_added` |
| `_hikvision_isapi_camera_added` | `_hikvision_isapi_performance_camera_added` |
| `_hikvision_isapi_switch_added` | `_hikvision_isapi_performance_switch_added` |

## Test infrastructure

`tests/conftest.py` now inserts the project root into `sys.path`
explicitly (previously the test file relied on `pytest`'s implicit
behaviour). This is a more portable setup and means the test file
can also be run directly via `python -m tests.test_isapi_client` or
similar tools.

## Compatibility

- Existing v0.5.0 users will see a **new integration** appear in
  HACS (`Hikvision ISAPI Performance`) rather than an update. The
  v0.5.0 `Hikvision ISAPI` integration should be removed manually
  from the integrations page to avoid the same data being read from
  two integrations.
- The integration can still be uninstalled and re-installed
  normally; the HACS default-repo workflow is unchanged.
